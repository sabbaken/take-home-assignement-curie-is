# План: подсветка TTS в PDF (PoC)

## 0. Каркас

- Vite + React + TS, `pdfjs-dist`, воркер через `?url`.
- Загрузить PDF и отрендерить одну-две страницы. Контейнер с тремя слоями: `canvas` → TextLayer → `<svg>`-оверлей.
- Cleanup в `useEffect`: `renderTask.cancel()` и `textLayer.cancel()` из-за StrictMode.

**Готово, когда:** страница рендерится, текст выделяется мышью, пустой SVG лежит ровно поверх.

## 1. Общая модель текста (~40 мин), `core/`

- `getTextContent()` → склеить `str` всех items в одну строку страницы. На `hasEOL` или разрыве между items добавить пробел.
- Для каждого символа запомнить, из какого item он пришёл и под каким индексом внутри item.
- `Intl.Segmenter` нарезает строку на слова (`isWordLike`) и предложения. Результат — диапазоны `[start, end)`.
- Общий интерфейс стратегии, чтобы обе реализации подключались одинаково:
  ```ts
  interface RectStrategy {
    getRects(start: number, end: number): Rect[]
  }
  ```
- Хелпер, который склеивает прямоугольники по строкам. Предложение на трёх строках даёт три бокса, а не десятки кусочков.
- **Как у Speechify:** хелпер «прямоугольники строк → один контур». Первая строка от начала предложения до правого края, средние целиком, последняя до конца предложения. Результат — один SVG `path` «лесенкой» со скруглёнными углами (радиус ~6px), без стыков между строками.

**Готово, когда:** в консоли видны слова и предложения с правильными диапазонами, а контур предложения рисуется одной фигурой.

## 2. Наивная стратегия

- Найти DOM-спаны TextLayer, соответствующие items. Их порядок совпадает с items, у которых есть `str`, но это надо проверить.
- Для подстроки создать `Range` на текстовом узле спана и вызвать `getClientRects()`. Координаты перевести относительно контейнера страницы.

**Готово, когда:** клик по слову подсвечивает его, и видно, где подсветка «плывёт».

## 3. Точная стратегия, основная часть

Это наш аналог того, что Speechify получает из коммерческого движка Nutrient: координаты по реальным глифам шрифта, а не по спанам с `sans-serif`.

- Позиция item: `tx = Util.transform(viewport.transform, item.transform)`. Базовая линия — `(tx[4], tx[5])`, размер шрифта в пикселях — `Math.hypot(tx[2], tx[3])`.
- Вертикаль: `top = baseline − ascent·size`, `bottom = baseline − descent·size`. Значения ascent и descent берутся из `textContent.styles[fontName]`.
- Горизонталь:
  - ``ctx.font = `${size}px "${item.fontName}"` ``. Шрифт уже зарегистрирован после рендера канваса.
  - Мерить **префиксы**, то есть `measureText(str.slice(0, i))`, а не отдельные символы. Так учитывается кернинг.
  - Масштабировать результат, чтобы полная ширина равнялась `item.width × scale`.
- Фолбэк: если шрифт не загружен (проверка через `document.fonts.check`) или это Type3, использовать наивную стратегию для этого item.
- Повёрнутый и вертикальный текст пропустить и упомянуть в README.

**Готово, когда:** в debug-режиме рамки ложатся на слова в середине длинных строк заметно лучше, чем у наивной стратегии.

## 4. UI демо

- **Debug-режим:** рамки вокруг всех слов. Лучше всего обе стратегии разными цветами одновременно, тогда разница видна сразу.
- **Переключатель** «Naive / Precise».
- Клик по предложению подсвечивает его и запускает чтение с этого места, как у Speechify. Предложение бледнее, текущее слово ярче.
- Стрелки для перехода к следующему или предыдущему слову.
- **Play:** `speechSynthesis` по предложениям, `onboundary` → `charIndex` → активное слово. Speechify на бесплатном плане делает так же, подход подтверждён. Если boundary-события не приходят, переходить по словам по таймеру.

## 5. Финал

- README: в чём проблема наивного подхода, как работает точный, известные ограничения (переносы, лигатуры, колонки, поворот).
- Два-три тестовых PDF: статья с arXiv в две колонки, текст с выравниванием по ширине, документ с несколькими шрифтами.
- Подготовить ссылку на демо и репозиторий.

**Итого ~4 часа.** Если не укладываешься, режь с конца: сначала TTS (достаточно навигации стрелками), потом поддержку нескольких страниц. Шаги 1–3 и debug-режим сокращать нельзя, это основная цель прототипа.

## 6. Интерфейс

Приложение состоит из одного экрана. PDF-страница лежит в центре на сером фоне с лёгкой тенью, как объект на доске Miro. Все элементы управления — плавающие панели по краям поверх фона, без шапки и сайдбаров. Каждая панель отвечает за одну группу действий.

```
┌──────────────────────────────────────────────────────────────┐
│ [≡ paper.pdf · 12 стр.] [Открыть]      [Naive|Precise] [Debug] [⚙] │
│                                                              │
│                  ┌────────────────────┐                      │
│                  │                    │                      │
│                  │   PDF-страница     │                      │
│                  │   (подсветка)      │                      │
│                  │                    │                      │
│                  └────────────────────┘                      │
│ [Легенда debug]                                              │
│        [⏮ ◀ ⏯ ▶ ⏭ ⏹ | 1.0x | Предл. 4/37]   [‹ 3/12 ›] [− 125% + ⤢] │
└──────────────────────────────────────────────────────────────┘
```

**Левый верхний угол — документ**

- Название файла и количество страниц.
- Кнопка «Открыть PDF». Файл также можно перетащить на любое место экрана.

**Правый верхний угол — режимы**

- Сегментированный переключатель «Naive / Precise».
- Кнопка Debug: рамки вокруг всех слов.
- Шестерёнка открывает поповер с выбором голоса и скоростью.

**Нижний центр — плеер** (главная панель, крупнее остальных)

- ⏮ предыдущее предложение, ◀ предыдущее слово, ⏯ play/pause, ▶ следующее слово, ⏭ следующее предложение, ⏹ стоп (сброс в начало).
- Скорость: 0.75 / 1 / 1.25 / 1.5 / 2x.
- Прогресс: «Предложение 4 из 37».
- Если голос не шлёт boundary-события, рядом маленький значок «синхронизация по таймеру» с подсказкой при наведении.

**Правый нижний угол — навигация и масштаб**

- Страницы: `‹ 3 / 12 ›`, номер можно ввести вручную.
- Зум: `−`, процент, `+`, «по ширине».
- Зум перерендеривает страницу в новом масштабе и пересчитывает модель текста. CSS-transform не подходит: текст на канвасе поплывёт и станет мыльным.

**Левый нижний угол — легенда** (только в debug-режиме)

- Цвета рамок наивной и точной стратегий.
- Количество найденных слов и предложений на странице.

**Пустое состояние** (PDF ещё не открыт)

- В центре большая зона «Перетащите PDF или откройте файл».
- Под ней две-три кнопки «Пример: статья arXiv / текст по ширине / несколько шрифтов», чтобы ревьюер сразу попал в демо без поиска своего файла.
- Лучше открывать первый пример автоматически при заходе по ссылке.

**Подсветка** (по мотивам Speechify)

- Предложение: светло-лавандовая заливка, около `rgb(224, 227, 255)`, одним контуром со скруглёнными углами (шаг 1).
- Слово: насыщеннее, около `rgb(171, 179, 254)`, скруглённый прямоугольник с отступом 1–2px.
- `mix-blend-mode: multiply`, чтобы текст под подсветкой оставался чётким.
- CSS-переход позиции слова ~80 мс, слово плавно перетекает.
- При наведении на предложение — лёгкая серая подложка. Клик запускает чтение с этого предложения.
- Автоскролл, чтобы активное слово всегда было в зоне видимости.

**Горячие клавиши** (подсказка по `?`)

- `Space`: play/pause.
- `←` / `→`: слово назад/вперёд.
- `Shift + ←` / `→`: предложение назад/вперёд.
- `Esc`: стоп.
- `+` / `−`: зум.
- `D`: debug.
- `N`: переключить Naive/Precise.

**Состояния**

- Загрузка: скелетон страницы.
- Ошибка: «Не удалось открыть PDF» с кнопкой «Выбрать другой».
- Страница без текстового слоя (скан): сообщение «На странице нет текста для озвучки».

Мобильная версия вне рамок задачи. Достаточно, чтобы панели переносились и не перекрывали друг друга на узком экране.

## Референс: как устроено у Speechify

Точность у них даёт PDF-движок с координатами по глифам, а не хитрость в оверлее. Наблюдения из веб-приложения на 19.09.2026:

| Что | Как у них | Что берём себе |
| --- | --- | --- |
| Рендер PDF | Nutrient Web SDK (бывший PSPDFKit) 1.3.0 на WASM в воркере, страница — `<img>` из blob | `pdfjs-dist` по условию, точность через метрики шрифта (шаг 3) |
| Оверлей | `<svg>` поверх каждой страницы, `viewBox` в координатах страницы | Такой же SVG-слой |
| Предложение | Один `path` «лесенкой», скругление ~6px, `rgb(224, 227, 255)` | Хелпер контура (шаг 1) |
| Слово | Скруглённый прямоугольник, `rgb(171, 179, 254)`, CSS `transition` | То же (шаг 6) |
| Озвучка (Basic) | Браузерный `speechSynthesis`, синхронизация по `boundary` и `charIndex` | То же (шаг 4) |

Премиум-голоса, скорее всего, идут с сервера с таймкодами слов. Это не проверялось.
